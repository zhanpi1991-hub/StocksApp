# Deployment guide: Render (API + PostgreSQL) and Vercel (frontend)

Nothing here deploys automatically. Follow the steps in order; each ends with a check you can run.

**Read this first: free-tier facts (from Render's docs).** A free web service sleeps after 15 minutes without traffic (about 1 minute to wake; price alerts and live polling pause while asleep). A free PostgreSQL database **expires 30 days after creation** (14-day grace, then deleted) and has **no backups**. Use a paid Render Postgres plan (or an external managed Postgres such as Neon or Supabase through `DATABASE_URL`) before real users store real data.

## Architecture

```
Browser ──HTTPS──> Vercel (static React build, SPA fallback, security headers)
   │
   ├──HTTPS (REST, CORS)──> Render web service: FastAPI in Docker ──> Render PostgreSQL (private network)
   └──WSS (live prices)───> same Render service (/api/ws, direct, not through Vercel)
```

The browser talks to the Render URL directly. `/api/*` is **not** proxied by Vercel (WebSocket proxying through Vercel rewrites is not documented), so the frontend is built with the API URL.

## Environment variables

### Render (backend)
| Variable | Value | Notes |
|---|---|---|
| `APP_ENV` | `production` | Set by `render.yaml`. Turns on startup safety checks. |
| `DATABASE_URL` | from the Render database (`connectionString`) | Set by `render.yaml`. `postgres://` and `postgresql://` are accepted. Must not be SQLite. |
| `JWT_SECRET` | random, 32+ chars | Generated by `render.yaml`. The app refuses to start with the default or a short secret. |
| `CORS_ORIGINS` | `https://<your-project>.vercel.app` | Exact origin(s), comma separated, no trailing slash, no `*`. Also used to validate WebSocket `Origin`. |
| `CORS_ORIGIN_REGEX` | optional, e.g. `https://stocksapp-[a-z0-9-]+\.vercel\.app` | Lets Vercel preview deployments call the API. Leave empty if unused. |
| `COINGECKO_API_KEY` | Demo key | Optional (works keyless, but heavily limited). |
| `FINNHUB_API_KEY` | key | Stocks, profiles, news, IPOs. |
| `TWELVE_DATA_API_KEY` | key | Stock charts, indices. |
| `FMP_API_KEY` | key | Statements, movers, screener. |
| `ENABLE_DOCS` | unset | `/docs` is off in production. Set `true` only temporarily. |
| `AUTH_RATE_LIMIT_PER_MINUTE`, `RATE_LIMIT_PER_MINUTE` | optional | Defaults 10 and 240 per client IP. |
| `CRYPTO_MARKETS_TTL`, `*_REQUESTS_PER_MINUTE/DAY` | optional | See `.env.example` and `docs/API_SETUP.md`. |
| `REDIS_URL` | optional | Not required. |
| `PORT` | injected by Render (10000) | Do not set. |

### Vercel (frontend, build time, **public values only**)
| Variable | Value |
|---|---|
| `VITE_API_URL` | `https://<your-service>.onrender.com/api` |
| `VITE_WS_URL` | optional; derived from `VITE_API_URL` when unset |

Never put provider keys or the JWT secret in a `VITE_` variable: Vite copies them into the public JavaScript.

## Render setup (Blueprint)

Prerequisite: the repo is pushed to GitHub with `render.yaml` at its root.

1. Render dashboard -> **New** -> **Blueprint** -> connect GitHub -> choose `zhanpi1991-hub/StocksApp`, branch `main`.
2. Render reads `render.yaml` and shows two resources: web service `stocksapp-api` (plan **free**, Docker, region `oregon`, health check `/api/health`) and database `stocksapp-db`.
3. Fill the prompted secrets (the ones marked `sync: false`). `CORS_ORIGINS`: your Vercel URL if you already know it; otherwise `https://example.invalid` for now and fix it in step 6. Provider keys can be pasted now or later.
4. **Apply**. Render builds `backend/Dockerfile`, starts Postgres, then boots the API. On every start the container runs `alembic upgrade head` and then uvicorn (single worker, `--proxy-headers`).
5. Check: open `https://<service>.onrender.com/api/health`. Expect `{"status":"ok","database":true,...,"env":"production"}`. `https://<service>.onrender.com/docs` should be 404.
6. After the Vercel deploy: Render -> service -> **Environment** -> set `CORS_ORIGINS` to the real Vercel URL -> save (Render redeploys).
7. If the service fails to start, open **Logs**: the app prints exactly which production setting is unsafe (for example "JWT_SECRET must be set...").

Manual alternative (no Blueprint): create a PostgreSQL database; create a **Web Service** from the repo with Runtime **Docker**, Root/Docker context `backend`, Dockerfile path `backend/Dockerfile`, Health check path `/api/health`, plan Free, and add the variables above. Use the database's **Internal Database URL** for `DATABASE_URL`.

## Vercel setup

1. Vercel -> **Add New Project** -> import `zhanpi1991-hub/StocksApp`.
2. **Root Directory:** `frontend`. Framework preset: Vite (auto-detected). Build command `npm run build` and output directory `dist` come from `frontend/vercel.json`.
3. **Environment Variables** (Production, and Preview if you want previews): `VITE_API_URL` = `https://<your-service>.onrender.com/api`.
4. **Deploy.** Copy the production URL into Render's `CORS_ORIGINS` (Render step 6).
5. Checks: open the site; the yellow "Cannot reach the StocksApp API" banner must not appear; open `/status` and confirm providers; open a deep link such as `/crypto/bitcoin` directly and refresh it (SPA fallback); register an account and add a watchlist item.
6. Any change to `VITE_*` variables needs a **redeploy** because they are baked in at build time.

`frontend/vercel.json` also sets security headers (CSP, `X-Frame-Options: DENY`, `nosniff`, HSTS, referrer and permissions policies). The CSP was tested locally against the production build (no violations). If you later add a new external image/font/API host, review `connect-src`/`img-src` there.

## Database migrations

- **Normal deploys:** automatic. The container runs `alembic upgrade head` before starting the server. It is safe for a single instance (do not scale to multiple instances without moving migrations to a pre-deploy step).
- **Check the current revision (Render Shell):** `alembic current`. Expect `0001 (head)`.
- **Run manually (Render Shell):** `alembic upgrade head`.
- **From your PC against the Render DB:** use the database's *External* URL, which requires TLS:
  ```powershell
  cd C:\Users\zhanp\StocksApp\backend
  $env:DATABASE_URL = "postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require"   # paste from Render; never commit it
  .\.venv\Scripts\alembic upgrade head
  ```
- **Creating future migrations:** autogenerate against a PostgreSQL database, not SQLite, so the generated SQL matches production. Review the file before committing. Never edit `0001` after it has been applied anywhere.
- **Rolling back:** `alembic downgrade -1` (drops data of that revision; take a backup first).
- **Backups:** Render free Postgres has none. Back up with `pg_dump "<external url>" -Fc -f stocksapp.dump` before upgrades; paid plans have managed backups.
- **Existing SQLite data:** the local `stocksapp.db` is development data only and is not migrated. Production starts empty.

## Manual steps remaining (after the code audit)

1. Push to GitHub (you commit/push; nothing here pushes).
2. Decide the database plan (free expires in 30 days).
3. Create the Render Blueprint, then the Vercel project, then cross-set `CORS_ORIGINS` and `VITE_API_URL`.
4. Add the four provider keys in Render (not in Vercel, not in the repo) and run the in-app **Data providers** page to confirm each shows Working/Ready.
5. Browser-test on the deployed URLs: register/login, watchlist, portfolio transaction, an alert, crypto and forex pages, a stock page with keys, WebSocket updates on a coin page.
6. Verify the WebSocket on Render (connects, receives `pong`, survives 2+ minutes idle) and confirm the rate limiter sees real client IPs (two different networks should not share a bucket).
7. Rotate any key that was ever pasted into chat or screenshots.
